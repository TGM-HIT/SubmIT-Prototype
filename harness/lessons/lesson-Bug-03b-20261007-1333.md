# Proposal

**Pause and resume human-dependent verification.** Bug-03b exhausted all three revise cycles because the required native-popup interaction was blocked by macOS permissions and some selectors had no available options; the orchestrator nevertheless requires failed closeout after cycle three. Update `harness/roles/orchestrator.md` to use the flow `in progress → awaiting-human → verification-only continuation → evaluator re-entry → done or failed`. Preserve and commit the exhausted run and its verdicts, mark it nonterminal, then create a separate continuation run that names the original run ID, final implementation commit SHA, and prior verdicts. Do not dispatch an Implementor or change the implementation in that continuation; dispatch the Evaluator on the same deliverable after human verification.

**Record evidence and constrain evaluator re-entry.** The verdicts correctly distinguish mocked or expanded-select checks from real collapsed-popup interaction, so later human acceptance must not silently turn unperformed checks into passes. Update `harness/roles/evaluator.md` to require a `human-verification.md` in the continuation run recording the attester, timestamp, original run ID and commit SHA, each acceptance item checked, the exact steps and environment/data used, the observed result, evidence paths or why evidence was not retained, and every unavailable or unperformed item. Give the Evaluator the original ticket, diff, handoffs, complete verdict history, and attestation; only count items directly supported by that record, keep unchecked items explicitly unverified, and pass only when the ticket's required acceptance is established.

**Represent the pause and terminal outcome in the ledger.** The plan currently has no nonterminal human-waiting status. Add `awaiting-human` to the status vocabulary in `harness/plan.md`; it is not a pass or failure. The orchestrator should set `done` only after evaluator pass and `failed` only after an explicit terminal failure or human decision to stop, and commit the continuation evidence, evaluator result, and ledger update together as the terminal run-artifacts commit. Until then, leave the ticket `awaiting-human` and preserve the original exhausted verdict unchanged.

**Allow explicit human acceptance as a separate terminal path.** A user authorized to accept the ticket may explicitly accept the current implementation after manual inspection, even if some evidence cannot be handed to the Evaluator. Record that decision, the accepted commit SHA, its scope, and any checks that remain unverified; preserve the evaluator's earlier revise verdict and do not rewrite it as a pass. This path should require an unambiguous acceptance instruction, not merely a statement that the change appears fixed.
