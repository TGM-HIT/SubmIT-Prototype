# Lesson proposal: account for documentation when tickets extend tooling

The first evaluation returned `revise` because adding `--seed-idea-owner` to the preview tool contradicted existing `frontend/DEV-GUIDELINES.md` guidance that the tool did not seed data, requiring a second implementation pass. Update [ticket-author.md](../roles/ticket-author.md) to require tickets that permit or depend on extending documented developer tooling to explicitly include a minimal update to its owning usage guide in scope and verification; this would make the documentation deliverable clear before implementation and avoid discovering the stale guidance only at evaluation.
