# Lessons proposal: Feature-02-20261008-0704

## Handoff artifact ownership

The run log records that the initial Implementor did not save `handoff-1.md`, and the revision Implementor explicitly said it had left `harness/runs/` unchanged because the role instructions prohibited editing that directory; a separate artifact-only Implementor was needed to finish `handoff-2.md`. Update `harness/roles/implementor.md` to explicitly permit creating or updating only the current pass's requested handoff file in the run folder, while continuing to prohibit edits to the ledger, run log, heartbeat, other run artifacts, and any commit of harness artifacts; align `harness/roles/orchestrator.md` dispatch instructions to name that exact output path. These role contracts own the change.

## Handoff heading format

The Implementor contract specifies headings as bare text, while `harness/gates/handoff-complete.java` accepts only headings with `##`, creating a mismatch between the role's exact format and the gate's required format. Change `harness/roles/implementor.md` to list the three headings with the literal `##` prefixes used by the gate. The Implementor role contract owns the change.

## Missing ticket ledger row

Preflight passed and the specification existed, but the run log found no Feature-02 row in `harness/plan.md`; the Orchestrator added it as `in progress` because its instructions did not define what to do when a valid ticket is absent from the index. Add a rule to `harness/roles/orchestrator.md` that, after preflight, treats the ticket specification as authoritative and inserts a missing plan row as `in progress` before dispatch, while recording the reconciliation in the run log; if the ticket specification itself is missing, stop before dispatch. The Orchestrator role contract owns the change.
