# Lessons proposal: Feature-03-20261008-0755

## Feasible role-specific manual checks

The ticket asked the Implementor to preview User Settings as an administrator using the documented testing profile, but the handoff and evaluator established that the profile only documented student and teacher accounts, which paused an otherwise passing implementation for a human check. Update `harness/roles/ticket-author.md` to require checking that every role named in an Implementor-performed manual scenario has an explicitly documented, authorized fixture; when that prerequisite is absent, the ticket must either make the item human-only with a clear authorized-account requirement or limit the Implementor-performed scenario to reachable roles. The ticket-author role contract owns this change.

## Granular human acceptance evidence

The pause checklist combined administrator save, shell update, persistence, cancel, validation/error behavior, and desktop/mobile layout into one row, while the human recorded only that name modification worked on desktop and mobile; the continuation evaluator had to distinguish that observation from the other substeps and rely on automated/prior evidence for them. Update `harness/roles/orchestrator.md` to split a compound human-verification criterion into independently observable checklist rows, each with its own result and evidence request, so a broad status cannot imply that unobserved substeps were verified. The Orchestrator role contract owns this change.
