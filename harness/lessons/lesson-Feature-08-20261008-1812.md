# Lesson proposal: distinguish generated artifact review from tracking

The first implementation force-added the entire ignored `contracts/openapi.yaml`, which had no tracked baseline and contained a variable server port; the Evaluator could not review a meaningful generated diff, so the Orchestrator later removed it from tracking and reverted the temporary scope-gate allowance. Update [ticket-author.md](../roles/ticket-author.md) and [implementor.md](../roles/implementor.md) to distinguish regenerating and inspecting required generated artifacts from committing them, and to check the repository's ignore/tracking convention before specifying or adding generated output; this would make contract verification reproducible without treating generation as a requirement to track ignored artifacts.
