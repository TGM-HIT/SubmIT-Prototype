# Bug-40. Provide reliable Compose shutdown and preconfigure an updated pgAdmin

## Intent

Starting Compose with a custom project and environment file succeeds, but a subsequent bare `docker compose down` fails while interpolating missing database and pgAdmin variables and does not stop that deployment. Compose re-parses the configuration and does not remember the startup arguments; omitting the project name can also target the wrong deployment. Provide a documented convenience workflow that consistently supplies both settings without weakening startup validation. Also provision the configured PostgreSQL connection as **SubmIT** in pgAdmin and retain the officially verified stable **9.19** upgrade. Finish verification safely without making ordinary startup checks depend on this ticket's Git history or lifecycle.

The owner accepted the recommendation to provide a convenience command rather than require literal bare `docker compose down` to work.

Follow-up to [Dev-57](Dev-57.md); do not amend its completed specification or historical runs. The [9.19 container documentation](https://www.pgadmin.org/docs/pgadmin4/9.19/container_deployment.html) documents server-definition import, its first-launch behavior, and the optional replace-on-startup setting.
